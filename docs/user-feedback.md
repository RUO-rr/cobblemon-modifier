# 需求驱动开发记录：玩家反馈 → 代码改动

本文件记录项目上线后收集到的**真实反馈**（来自项目作者的 B 站教程视频评论区与私信），
以及每一条对应的调查结论与代码改动。它是 [ARCHITECTURE.md](../ARCHITECTURE.md) 第六章的展开版。

> 说明：反馈原文按玩家原话保留（含错别字与口语），便于回溯"当初到底在抱怨什么"。

---

## 一、反馈收集与处理流程

```
1. 收集：评论区 + 私信原文（含截图、日志）
2. 归类：数据源 / 形态 / 输入校验 / 概念误解 / 新功能
3. 验证：先查"到底发生了什么"——读游戏日志、扫真实整合包、反编译 Cobblemon
4. 改动：改代码 + 加回归测试
5. 回写给作者实测（游戏内验证），通过后记录到本文件
```

**一条重要经验**：玩家的描述 ≠ 需求本身。
例如"解除 mega 限制"最初被理解成"要能编辑 mega 形态"，追问后才知道真正想要的是
"解除同时只能有一只 Mega 的数量限制"。**先确认再动手**省下了一整轮返工。

## 二、反馈逐条对照

### F-01 改完某些宝可梦"进对战变得更弱 / 大扣血"

> 玩家原文（私信）：
> "大佬 种族值改了之后 进入对战就变了 变得更弱了 这是怎么回事呀"
> "5.2re 开战之后就变成这样了 大扣血"

**调查**：读日志与真实数据后发现，出问题的不是"改错了"，而是"改坏了别的形态"。
Cobblemon 数据格式里形态不带 `baseStats` 表示**继承本体**，而当时的实现把"缺字段"当成"空值"，
给这些形态写进了一串 `0`。实测 **366 个形态里有 223 个**属于这种情况，涉及 105 个物种
（Mega / Gmax / 阿罗拉 / 伽勒尔 / 洗翠）。

**改动**：

- 形态没有 `baseStats` 时保持继承，只有用户确实改动某一项时才写入
- 界面改为显示"继承来的值"（原来是显示 0，误导用户去改）
- 加回归测试把这条钉死
- 同一类问题在特性插件里一并修复（形态没有 `abilities` 时被写成空数组，导致"改本体把形态特性清掉"）

### F-02 "图鉴显示改了，但对战没变"

> 玩家原文（评论区）：
> "主播，为什么改完之后只有图鉴里会显示，但是实际上对战没有改过来了呢"

**调查**：反编译确认 Cobblemon 1.7.3 的战斗引擎是**内置的 Pokémon Showdown**（跑在 GraalJS 里），
物种数据通过注册表推送。于是做了"保存后自动 `/reload` + `/reloadshowdown`"，
**结果被真实日志推翻**：

```
Cobblemon data registries are only loaded once per server instance
as Pokémon species are not safe to reload.
```

而且那次 `/reload` 让游戏卡了 13.6 秒却毫无收益。

**改动**：**撤销该功能**，把提示改成实话——"重进世界后生效（不用重启游戏）"；
同时确认物种数据在每次世界加载时都会重新读取并推送给战斗引擎。

### F-03 "某些宝可梦改不了"（喷火龙 / 蒂安希 / 固拉多）

> 玩家原文（评论区）：
> "UPUP，jorstear的去吧方可梦大师5.9，喷火龙的特性和种族值改不了，其他精灵都可以正常改"
> "蒂安希还是改不了" / "为什么固拉多改了没有效果"

**调查**：整合包大量使用数据包提供/覆盖宝可梦数据，而工具当时只扫 `mods/*.jar`，
这些精灵**在列表里根本看不到**。

**改动（P2 数据源补全）**：

- 扫描范围扩到 `global_packs/required_data`、`resourcepacks`、`global_packs/jostar_overrides`
- 优先级以 `level.dat` 的真实加载顺序为准（越靠后越高）
- 同名数据在多个来源各有一份时按 JSON 路径去重
- 收紧"是不是宝可梦"的判定（必须有 `baseStats`），避免把 1214 条图鉴条目当成宝可梦

### F-04 "给地龙加龙之舞学不会"

> 玩家原文（评论区）：
> "能不能加上修改技能，我想给地龙加个龙之舞"
> （私信补充）"我已经添加了 tm:dragondance 而龙之舞的学习器道具我已经使用了，也不能给烈咬陆鲨学习"

**调查**：地龙的招式表被数据包**整体替换**了——

```
resourcepacks/§eJoStar§c大集合.zip
  └─ data/move_calibration/species_additions/garchomp_move.json
       { "target": "cobblemon:garchomp", "moves": [ 79 条 ] }   ← 没有龙之舞
```

机制上 `SpeciesAdditions$Addition` 是 `(物种属性, 新值)`，**整体替换而非合并**；
而应用顺序是遍历 `HashMap`，**与数据包优先级无关**。整合包里 **4693 个覆盖文件覆盖 1074 个物种**，
`moves` 被覆盖 2082 次，其中 **1025 个物种的招式表被 ≥2 个文件同时接管**。

**改动**：

- **方案 A**：把 `species_additions` 也纳入列表，可直接编辑
- **方案 B1 扇出写入**：保存时把变化字段同步写进该物种的**所有**来源文件；
  `还原原版` 也一起清理，避免半还原
- **P4 技能修改**：新增"技能修改"插件（新增空槽 / 改等级 / 删除），
  并用 1386 条已知招式表做输入校验
- **P4 第二档（3.1.0）招式数据修改**：玩家说的"改招"其实有两层——
  学得到哪些招式（学习表，上面这条）和招式本身有多强（威力 / 命中）。
  后者也补上了：主界面 **招式数据** 按钮，基础招式 952 条与数据包自定义招式 435 条都能改，
  招式脚本里的函数体原样保留，改错可一键还原

### F-05 "解除 mega 限制"

> 玩家原文（私信）：
> "谢谢，修改器很好用，未来会开发改招和解除mega限制吗"
> （作者澄清）"原意是想解除 mega 进化宝可梦最大只可同时存在一只的限制"

**调查**：mega_showdown 自带该开关（`config/mega_showdown/config.json` 的 `multipleMegas`），
其配置类有公开的 `load()` 可反射热重载。坑点：同目录下那份 `mega_showdown-common.toml`
是**旧版遗留、已经不生效**，照着它改会完全没效果。

**改动（P3）**：主界面新增 **多Mega** 开关按钮，写入 JSON 后反射热重载，立即生效。

### F-06 "改完进不去世界"

> 玩家原文（评论区）：
> "upup，改完之后进不去了，这是咋回事"
> （作者回复）"是不是改的特性，改特性单词打错了就进不去"

**调查**：特性 / 招式这类 id 写错会让数据包加载失败，而当时的界面**不做任何校验**。

**改动**：加入输入校验——招式必须命中 1386 条已知招式表，特性需在白名单内；
非法时拒绝保存并给出具体提示（例如"未知招式 id：dragondanc，请检查拼写"）。

### F-07 "这个是只修改我队伍里的那一只吗？"

> 玩家原文（评论区）：
> "upup 这个是只修改我队伍里的那一只宝可梦的种族值吗？"
> "哪些精灵是啥编号？我怎么看？"
> "有没有直接查看魔改特性英文的办法"

**调查**：属于概念与可发现性问题——工具改的是**物种数据**（对所有该种宝可梦生效），
且没有便捷的查询入口。

**改动**：README 与界面提示写明"改的是物种数据、需重进世界生效"；
新增 **字段查找**（按图鉴编号 / 名字 / 特性搜索并跳转）；招式/特性字段带中文标注。

### F-08 "改完只有文件变了、游戏里没变"

> 玩家原文（评论区）：
> "大佬，用了以后改了没效果咋办？改完以后进游戏发现游戏数据没变，但是查的文件又没有问题，是改完以后的数值，这怎么办？"

**调查**：这条与 F-01/F-04 同源，属于"写入成功但被更高优先级的来源覆盖"或"需要重进世界"。

**改动**：扇出写入 + 明确区分"文件已写"和"游戏内生效"的提示文案。

### F-09 性能类反馈（扫描慢、像卡住）

> 现象：点击"加载宝可梦数据"后进度条长时间不动，作者一度怀疑卡死。

**调查**：原始实现每读一个 JSON 就重新打开一次压缩包（8968 个候选 = 8968 次 open，
其中反复打开 135MB 的 Cobblemon 本体）。

**改动**：

- 改为"一个压缩包只打开一次 + 批量读取"：实测 **35~126 秒 → 0.41 秒**
- 收集候选阶段也会向界面推送状态文字（不再像卡住）
- 扫描任务改为 `catch (Throwable)` + `finally`，异常也会复位进度条；加入扫描闸门防止重复点击堆任务

### F-10 "刷新率改了没效果"

> 玩家原文（私信）：
> "说实话我改了之后成功了，但是貌似不明显……哪怕给伊布加了 10000 的权重还是没有见到"

**调查**：单只刷新率走的是往世界数据包写 `spawn_pool_world` 覆盖，
但该整合包有 8 个全局数据包自带 `spawn_pool_world`（其中一个还含同名文件），
工具的基线来源与游戏实际加载的那份不一致；而且必须重进世界才生效。

**改动**：**下架"单只刷新率编辑"**，只保留验证有效的"全局稀有等级权重"
（写 `best-spawner-config.json` + 反射热重载，立即生效）。

### F-11 "ZA 超进化的种族值要改 ZA 包才有效"

> 玩家原文（反馈）：
> "我记得之前我在视频里提到过某些特殊宝可梦要单独改某些包才有效。
> 比如 za 的超进化宝可梦的种族值要改 za 包里的种族值才有效"

**调查**：ZA 的超进化形态（含种族值/特性）定义在它自己的 `species_additions` 里：

```
[宝可梦-ZA]zamega-fabric-1.7.6.jar
  └─ data/cobblemon/species_additions/generation3/absol_mega.json
       { "target": "cobblemon:absol", "forms": [ { "name": "Mega-Z", "baseStats": {...} } ] }
```

**改动**：扇出写入覆盖到该物种所有来源；`forms` 采用**按形态名合并**，
既能把改动写进 ZA 的文件，又不会删掉它独有的超进化形态。

## 三、这一路"按反馈开发"带来的架构变化

| 反馈类别 | 直接造成的架构改动 |
|---|---|
| 改了没效果 / 改不了 | 单一数据源 → 多数据源 + 优先级 + 去重 + **扇出写入** |
| 改完进不去世界 | 无校验 → **输入校验层**（招式表 / 特性白名单） |
| 图鉴与对战不一致 | 撤销无效的热推送方案，改为**准确提示** |
| 刷不出、看不清 | 新增**字段查找**与中文标注 |
| 像卡死 | 扫描**批量读取**优化 + 进度状态推送 + 异常复位 |
| 想要更简单的开关 | 把指令与配置封装为**界面按钮**（多 Mega、稀有等级权重） |

反向的例子同样重要：**`resourcepacks` 扫描**一度因为"那里有 2.3 GB 材质包"被考虑移除，
但实测列条目只要 63 毫秒、影响很小，于是保留（只做同名去重）——**用数据而不是直觉做决定**。
